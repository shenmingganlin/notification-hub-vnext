# 1. 名字

| 词 | 是什么 |
|---|---|
| 数据 | 通知里的字和图。标题写什么、头像哪张、进度多少。 |
| 卡面 | 一棵零件树。根就是以前叫「卡片」的那块板。 |
| 通道 | 一种飞法一个池。只承载根零件。 |
| 方案 | 能保存、导出、给别人用的那一包：通道 + 卡面 + 素材。 |

不用并列的词：种类、内容轴、配方、视觉模式。

# 2. 卡面：根带着孩子

以前的卡片 = **根零件**。

- 别的零件只能待在根里面，跟着根走，不能自己漂在通道里。
- 根有两个框：
  - **可点框**：通道拿去堆、去飞、去点。悬停和点击只认这里。
  - **绘制框**：可以更大。皮和以后的粒子画在这里，画出可点外面也不改占位。
- 标题、正文、头像、关闭、进度，都是孩子零件。没有「底下印死的字」。

## 2.1 几何底

零件的底只有很少几种：字、图、块（矩形）、圆、条、钮。

「消息卡 / 进度卡 / 重要卡」不是种类，是根里面摆好的一捆几何底，可以存成方案里的起点。

## 2.2 皮长在每个零件上

不单列皮肤大类。每个零件自己有外观：填充、描边（轮廓粗细/颜色/虚实）、字色、圆角、透明度。

给根设皮，就是以前那张「卡片皮肤」。给头像设皮，只影响头像。

**词表**（可选）：给颜色起名，例如「标题色」。零件可以写死一个色，也可以引用名字。换一套名字，引用它的零件一起变。没有词表也行，每个零件自己调。

一个数只有一个主人。头像宽只在头像上。可点宽只在根上。颜色要么零件自己写，要么引用词表，只留一份。

## 2.3 交互长在零件上

描边是外观。悬停放大、变色是交互。默认没有，加上才有。

特效不是这类：入场 / 停着 / 离场跟通道时钟走，不要把鼠标放大写进入场粒子。

点到谁算谁：可点框里最上面那件。绘制框溢出的皮不抢鼠标。

## 2.4 怎么编

- 没选中孩子：在编根（可点框、绘制框、飞法）。
- 选中哪个零件：只出那一件的设置。
- 新加零件：默认放空位、不压别的件。允许拖去重叠。挡住是层级，列表里调上下。关闭默认在最上面。

在中枢里编卡面的人（你，或把中枢当工作室用的人）是同一套编辑。外部插件不当作者交脸。自由是全能改，不是一打开铺满。

默认：不飞。根上只有标题、正文两个孩子。

# 3. 通道：一种飞法一个池

通道是池子，不是脸。

- 默认两个池：堆叠、弹幕。突脸及以后每多一种飞法，多一个池。
- 池里不混飞法。
- 通道不绑整张脸、不绑皮。只留：这种飞法、屏幕区域、容量、生命周期时钟、和谁隔离。
- 卡面自己带着零件树进场。通道可以有一张**缺省卡面**（没绑树时用那张字板）。

## 3.1 飞法在根上

飞法是根零件的属性。根上选飞法 = 走进对应的那个池。孩子不选飞法。

同一池里的根一起挤：堆叠共一个角，弹幕共一条带。一条通道坏了不拖死另一条。

通道是我们自己的。不为外部插件开池。他们的通知走进你为这条事件选的池。

弹幕的速度、轨道、带、间距，是**弹幕池**的属性，不是某个孩子零件的属性。

## 3.2 内外层

不是一类属性，不要做进同一组设置。

| | 谁做主 | 能不能每张卡不一样 |
|---|---|---|
| 内层：这张根里有哪些孩子、填充描边、词表、悬停 | 这张卡面 | 能。不同事件可以完全不同的脸 |
| 外层：同轨间距、异轨间距、卡片缝、停靠、速度、容量 | 池 | 不能。全池一份 |

自己的插件：不同事件、同一种飞法、不同卡面，可以跑在同一个池里共同运作。通道只看见根的可点框和飞法。

事件若要换物理，只能换飞法（换池），不能给单张卡开小灶缝。

# 4. 数据怎么进卡面

事件带来数据。零件用绑定把它画出来：这个文字零件绑 `title`，这张图绑 `avatar`。

数据不会被「挡住」。挡住的只是谁画在谁上面。

是否重要、是否错误，是数据。让某个零件去引用状态色，不要做成一种新零件。

## 4.1 外部插件：只报事件和数据

外部插件是事件源，不是舞台主。

只许交两样：

```text
事件名    如 mail.new（带来源前缀，防撞名）
数据      title / body 以及其它键
```

不交建议卡面、不交声音、不交飞法。不为他们开池。脸、声、进哪个池，全是中枢「应用于事件」里绑的。

发现方式：我们挂一个公开入口（胚胎是 `NotificationApi.ingestEvent()`），别人来喊。不扫描已装插件，不订阅别人内部事件。喊了才认得。分类走已有的 `external_call`。

第一次某事件进来：

1. 写入通知历史
2. 事件名出现在「应用于事件」，可绑卡面 / 声音 / 飞法
3. 还没绑：缺省字板只吃 `title` 和 `body`，进你的默认池；全局安静则不出卡
4. 多出来的键先躺在数据里；以后零件绑了才画

装十个插件仍是这一个口、我们自己的两个池。声音和视觉仍分开，失败互不拖死。

底层还没把这口做成稳定外部 API。那是解冻之后的公共 API 阶段，位置已经留好。

# 5. 和现在底层的关系

已经接到真卡的：

- 两个池的雏形：堆叠、弹幕（Native 的 Stack / Shelf）。
- 根的一部分：宽、高、圆角、透明度、底色、底图。
- 字：标题 + 正文，坐标写死在绘制里。不是零件树。
- 可点：卡的几何 + 关按钮死位置。

还没有的（目标，不是 0.1.6）：

- Native 读零件树再画。
- 孩子零件、两框、每件自己的皮、描边、悬停、词表、绘制溢出。
- 通道不再挂整份 `visualProfileId` 当脸。

配置包仍只含声明和素材，不含代码。自由是声明一份卡面，不是脚本。

0.1.6 工作室正好是这套的窄切片：选池（堆叠/弹幕）+ 调根的宽高圆角。名实可以对上，树还没长出来。不要在验证中途改工作室排版 / 协议 / Native 声音 / 历史。

# 6. 下一刀（仍是计划）

本体到此为止，不再加轴。

产品实现顺序（解冻之后才动代码）：

```text
Native 能读一棵最小零件树（根 + 标题 + 正文，仍默认安静）
  ↓
孩子：图 / 关闭 成为真零件（选中才出设置；加件默认不叠）
  ↓
每件的描边与填充
  ↓
悬停等交互
  ↓
词表、绘制框溢出
  ↓
突脸 = 新的一种飞法、新的一个池
```

不恢复六种卡片种类。不把零件样式写死在 C++ 坐标里。不把日常做成「少旋钮」、作者做成另一套。

声音、通知历史独立。视觉失败不得拖死它们。看得见的都能用；未实现的标出来。
