# ADR-005：卡面、通道、外部事件

- 状态：Accepted
- 日期：2026-09-13
- 范围：视觉本体与外部插件接入（计划层；0.1.6 产品仍冻结）
- 关联：`docs/superpowers/plans/2026-09-13-card-face-and-channel.md`；取代 ADR-002
- 取代：ADR-002（卡片种类与出现方式轴分离）

## 背景

ADR-002 把「卡片种类」定为内容结构轴，与出现方式分开。随后的设计谈话表明：种类对用户是空轴；内容槽与零件几何抢权；外部插件若申请独立通道会在同一角挤出多摞。需要一条与现行设计一致的决策。

## 决策

1. **卡面**是一棵零件树。根就是以前的卡片。孩子只能待在根里。根有可点框与绘制框。皮、描边、交互长在每个零件上。不单列皮肤大类，不用卡片种类作为用户轴。
2. **通道**是一种飞法一个池，只承载根。飞法是根的属性（选飞法 = 进对应池）。外层（缝、速度、容量、停靠）全池一份。内层（脸）每张卡可以不同。不同事件、同一飞法、不同卡面，可以在同一池共同运作。
3. **外部插件**只报事件名和数据。来喊才认得。不开池，不交建议卡面 / 声音 / 飞法。分类 `external_call`。公开入口是中枢的一个 `notify`（或沿用 `ingestEvent`）口，别人调用；不扫描已装插件，不按插件订阅 bus。
4. 声音与视觉独立。配置包不带代码。看得见的都能用。

## 后果

- ADR-002 的种类轴、总纲「外部插件申请独立通道」不再作为实施依据。
- 解冻后的实现顺序见 09-13 计划 §6：先让 Native 读最小零件树，再孩子零件与每件的皮；突脸 = 新池。
- 聚合、钉住、跟随、场景若做，也是一种飞法一个池，到时单独立项，不在本 ADR 展开。
- 0.1.6 工作室 / 协议 / Native 声音 / 历史不因本 ADR 改动。
