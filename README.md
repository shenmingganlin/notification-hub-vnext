# Notification Hub vNext

HanaAgent 的 Windows 桌面通知场景。

试用版 · `0.1.8` · Windows · MIT

> 这不是完成品。卡片能飞、声音能响、工作室能配，但体验还没收口，后面还有整条路没铺。请当试用，不要当默认生产插件。

它和现有的 [Notification Hub 0.2.1](https://github.com/shenmingganlin/notification-hub) 是两套插件，互不影响。本仓库的插件 ID 是 `notification-hub-vnext`。

---

## 现在的位置

桌面通知不再只是一条记录。它是一张卡，占一个槽，按飞法待在屏幕上：

- **堆叠**：停在角上，新卡来了旧卡让位。
- **弹幕**：平着飞过屏幕，画在一座幕布上。

工作室已经能改通道和卡面。声音有独立的库和规则。配置包可以带走样子，但不带走通道法律。

许多表面仍粗糙：通知中心、设置页、工作室手感都还在打磨。入场出场、淡入、粒子、路径飞都还没有。

安装请用 [v0.1.8 试用包](https://github.com/shenmingganlin/notification-hub-vnext/releases/tag/v0.1.8)。整包重装，不要热替换。

## 已经实现

### 桌面飞法

- 堆叠与弹幕是两座池，一种飞法一个池。
- 堆叠落点：跟随 / 瞬移。新位：占角 / 新位。走线：关、平行、蛇形、回字。
- 弹幕走幕布：位移由合成器做，卡面只在内容变时上传。默认带宽不改。
- 点穿（不挡点击）。悬停加亮、悬停暂停各是一颗开关，默关；点穿开着时两颗都不能用。
- 标题 / 正文可跟事件取字，或自定义写死。写死只改字，不让卡一直挂着。

### 工作室

- 一屏工作室：上通道，下卡片。
- 实时预览对着当前草稿，没有假舞台。
- 卡面是根零件带着孩子：标题、正文、关闭、图标、助手名。
- 视觉配置可应用到指定事件。全局开关能关掉整条桌面视觉。

### 声音

- 常驻音频引擎，跟视觉链路分开。声音失败不挡住通知。
- 自定义音库、事件绑定、组合规则、实验台和规则解释。
- 支持 WAV、MP3、M4A、AAC、WMA（依赖本机 Media Foundation）。

### 通知与诊断

- 通知中心保存历史，列表先给摘要。
- 设置按领域拆页，侧边栏只做轻量入口。
- 诊断页解释配置、运行时和恢复，不把通知正文写进诊断。

### 配置包

- 一个 `.nhvisual` 里可以有多份配置。
- 只带样子、事件绑定、卡面和素材指纹，不带底图/字体文件，也不带通道法律。
- 导入时若缺底图或字体，会先问再写。保存本机配置包不再为此拦住。

## 可能碰到的问题

试用期里，这些问题是预期内的，不是「装坏了」。

- **手感未收口。** 工作室、设置、通知中心都能用，但间距、层级、措辞和操作节奏都还有别扭处。
- **必须整包重装。** 覆盖文件或热替换容易让运行时和设置对不上。改「启用桌面通知卡片」之后，还需要重启 Hana。
- **配置包不带通道。** 导入后带子、净空、落点、走线仍是这台机器原来的法律。看起来像「包没生效」，其实是立法如此。
- **点穿会关掉悬停。** 点穿开着时，加亮和暂停都禁用。空处本来就不挡点击。
- **卡片会直接出现。** 现在只有持续落点，没有入场、出场、淡入淡出。不要按「飞进来」去等动画。
- **弹幕只做平动。** 函数轨迹、路径飞还没有。现行 ticker 就是平着走。
- **两套插件可以同时开。** 和 0.2.1 并存时，桌面上可能出现两套卡片。试用时建议先关掉其中一套。
- **素材对不上。** 配置包按指纹认图、认字体。库里没有，导入会问；本机删过图，零件上可能还留过空引用，保存时会丢掉。
- **只要 Windows。** 需要较新的 HanaAgent，插件是 full-access。损坏或不支持的音频会静音，不应挡住通知本身。
- **通知中心不是最终样子。** 图像化顶栏、完整主题、更顺的筛选和详情，都还没按设计落地。

遇到卡顿：堆叠跟随只应挪窗口，不应每帧重画整张卡。弹幕不应每帧整带上传。若明显掉帧，请带着诊断导出再谈，不要先加特效。

## 以后可能做

没有排期，也没有承诺做完的时间。只是已经看见的方向。

**新飞法**

- 突脸：新池，不是在堆叠或弹幕上打补丁。
- 路径飞：函数轨迹另立法、另限制，不接进现行平动弹幕。

**运动与特效**

- 入场 / 出场位移。
- 卡片特效：淡入淡出等，只改单卡透明度，不占槽、不改通道。
- 粒子：另一门，尚未立法。

**产品表面**

- 通知中心的图像导航与更完整的页结构。
- 工作室和设置的视觉收口。
- 外部插件主动发通知的 API（分类已留口，能力还没接）。

明确不做：再开一轮皮肤刀、裁切。底图已经进根零件。

## 安装

1. 从 [Releases](https://github.com/shenmingganlin/notification-hub-vnext/releases/tag/v0.1.8) 下载 `notification-hub-vnext-0.1.8.zip`。
2. 在 Hana 里整包安装。不要只换其中几个文件。
3. 如需桌面卡片，确认插件设置里启用了桌面通知，然后重启 HanaAgent。

本试用包 SHA256：

```text
5D6CDE1A76BE9420435030933C92E25F33FA124C32039BBC1BD804AFD4ED8289
```

开发构建：

```powershell
npm test
cmake --preset debug-vs2026
cmake --build --preset debug-vs2026
```

正式打安装包请看 `scripts/package-release.ps1`。试用迭代包走 `scripts/pack-try-zip.py`。

## 仓库

| 路径 | 职责 |
| --- | --- |
| `plugin/` | Node 领域、页面、设置、协议适配 |
| `runtime/` | C++ 场景运行时：窗口、布局、幕布、音频 |
| `schemas/` | 版本化协议 |
| `docs/` | 词表、ADR、计划 |
| `tests/` | Node 与协议测试 |
| `legacy-reference/` | 旧版对照，不进安装包 |

词表在 `CONTEXT.md`。当前状态在 `CURRENT-STATUS.md`。飞法与卡面以 `docs/superpowers/plans/2026-09-13-card-face-and-channel.md` 为准。发布版本以根目录 `VERSION` 为准，须与 `package.json`、插件清单一致。历史诊断文件不参与现行核对。

架构上，Node 管通知语义和配置；Native Runtime 管窗口、布局、渲染和音频；两者经 Named Pipe 通信。vNext 只用自己的 Runtime、自己的数据目录、自己的管道名。
